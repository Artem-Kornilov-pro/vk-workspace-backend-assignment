# msgfmt

Часть 1: преобразование подмножества Markdown в текст без разметки и список диапазонов стилей. Позиции считаются в кодовых единицах UTF-16. C++17, только стандартная библиотека.

## Сборка и тесты

```sh
cmake -S msgfmt -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
ctest --test-dir build --output-on-failure
```

Опции CMake:

| Опция | По умолчанию | Назначение |
|---|---|---|
| `MSGFMT_SANITIZE` | `OFF` | сборка с `-fsanitize=address,undefined` (ошибки UBSan фатальны) |
| `MSGFMT_WERROR` | `OFF` | `-Werror` в дополнение к `-Wall -Wextra -Wpedantic` |

Проверка под санитайзерами:

```sh
cmake -S msgfmt -B build-asan -DCMAKE_BUILD_TYPE=Debug -DMSGFMT_SANITIZE=ON -DMSGFMT_WERROR=ON
cmake --build build-asan && ctest --test-dir build-asan --output-on-failure
```

Проверено на Ubuntu 24.04 (GCC 13.3, Clang 18) и macOS (Apple Clang 21): сборка без предупреждений, все тесты проходят в том числе с санитайзерами.

## Запуск

```sh
$ printf '**жирный _и_ курсив**' | build/msgfmt
{"text":"жирный и курсив","ranges":[{"style":"bold","offset":0,"length":15,"url":""},{"style":"italic","offset":7,"length":1,"url":""}]}

$ printf '2 * 3' | build/msgfmt escape
2 \* 3

$ printf '\xff' | build/msgfmt; echo "код $?"
{"error":"invalid_utf8"}
код 2
```

| Команда | Вход | Выход | Код |
|---|---|---|---|
| `msgfmt` | разметка, UTF-8 из stdin | JSON `{"text", "ranges"}` и перевод строки | 0 |
| `msgfmt escape` | текст, UTF-8 из stdin | текст, где каждый служебный символ предварён `\` | 0 |
| любая из двух | невалидный UTF-8 | `{"error":"invalid_utf8"}` | 2 |
| неизвестные аргументы | — | подсказка в stderr | 1 |

Вход читается целиком и как есть: завершающий перевод строки (например, от `echo`) — часть текста. Поэтому в примерах используется `printf`.

## Устройство

| Файл | Назначение |
|---|---|
| `src/utf.cpp` | строгое декодирование UTF-8, кодирование обратно, длина в UTF-16 |
| `src/chars.cpp` | классы символов: пробельные, буквы/цифры, служебные |
| `src/parser.cpp` | разбор разметки |
| `src/escape.cpp` | команда `escape` |
| `src/json.cpp` | сериализация в JSON |
| `src/main.cpp` | CLI |
| `tests/` | юнит-тесты на собственном мини-каркасе и CLI-тесты (эталонные `cli/*.in` → `cli/*.out`) |

Разбор — рекурсивный спуск по кодовым точкам за один проход слева направо. Встретив открывающий маркер, парсер ищет ближайший подходящий закрывающий в пределах текущего сегмента; если он найден, содержимое разбирается как вложенный сегмент, ограниченный этим закрывающим маркером, иначе маркер выводится как обычный текст. Из-за того, что вложенная конструкция обязана закончиться внутри внешней, частичные пересечения диапазонов невозможны.

Результаты поиска закрывающих маркеров запоминаются в пределах сегмента: если из позиции `p` закрывающего нет, его нет и правее `p`; если найден `q`, то из любой позиции до `q` найдётся он же. Благодаря этому разбор линеен даже на входах вида `_a _a _a …` или `[[[[…`, где у каждого открывающего маркера нет пары (это проверяет тест `parse.large_inputs_are_linear`).

Диапазон добавляется в момент открытия, итоговая сортировка `std::stable_sort` по (offset ↑, length ↓) сохраняет порядок открытия для совпадающих диапазонов — правило 12.

## Принятые решения

- **Буква или цифра** (правило 3 для `_`): ASCII-буквы и цифры, а также буквы и цифры основных алфавитов — латиница с диакритикой, греческий, кириллица, армянский, иврит, арабский, деванагари, тайский, грузинский, CJK, кана, хангыль, полноширинные формы — и комбинируемые диакритические знаки U+0300–U+036F как часть слова. Эмодзи, знаки препинания и символы буквами не считаются, поэтому `💅_ок_` даёт курсив.
- **Пробельный символ** (правила 3–5, 8): все кодовые точки со свойством Unicode `White_Space`: U+0009–U+000D, U+0020, U+0085, U+00A0, U+1680, U+2000–U+200A, U+2028, U+2029, U+202F, U+205F, U+3000.
- **Соседние символы** для правил 3–5 берутся из исходного текста, а не из результата: `**_а_**` даёт и жирный, и курсив, потому что перед `_` стоит `*`.
- **Непустое содержимое**: закрывающий маркер не может стоять сразу за открывающим, поэтому `****` и `[](u)` — обычный текст, а диапазонов нулевой длины не бывает.
- **Неудачный `**`** выводится целиком и разбор продолжается после него: `**не закрыто` → `**не закрыто`.
- **Экранирование при поиске закрывающего**: пары `\` + служебный символ пропускаются, поэтому `**a\**` — обычный текст `**a**`. Внутри code экранирование не действует: `` `a\` `` → code `a\`.
- **Текст ссылки** заканчивается на первом неэкранированном `]`; экранированный `\]` в него входит: `[a\]b](u)` → ссылка с текстом `a]b`. Если первый `]` не подходит (перед ним пробельный символ или за ним нет `(url)`), `[` выводится как текст.
- **URL** берётся как есть, до первого `)`, без обработки экранирования: `[a](u\v)` → url `u\v`, `[a](b(c))` → url `b(c` и `)` после ссылки.
- **Конструкция внутри конструкции** должна закрыться внутри неё: в `**a `b**` c**` жирный заканчивается на первом подходящем `**`, а незакрытая внутри него `` ` `` становится текстом.
- **JSON**: поля выводятся в фиксированном порядке без пробелов; экранируются `"`, `\` и U+0000–U+001F (`\b \f \n \r \t`, остальные — `\u00XX`), всё остальное — UTF-8 как есть. После объекта выводится перевод строки.
- **UTF-8**: отвергаются обрывы последовательностей, лишние байты продолжения, избыточные (overlong) записи, суррогаты U+D800–U+DFFF и значения выше U+10FFFF. BOM считается обычным символом U+FEFF.

## Известные ограничения

- Таблица букв и цифр упрощённая и не совпадает с категориями Unicode `L*`/`Nd` полностью: например, буквы редких письменностей вне перечисленных диапазонов считаются «не буквами», и `_` после них может открыть курсив.
- Вход читается в память целиком.
- Нормализация Unicode не выполняется (по условию): `é` из двух кодовых точек даёт два символа и длину 2.
